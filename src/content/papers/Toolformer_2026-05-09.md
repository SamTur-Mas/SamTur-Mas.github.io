# Toolformer: Language Models Can Teach Themselves to Use Tools

**arXiv**: [2302.04761](https://arxiv.org/abs/2302.04761)
**作者**: Timo Schick, Jane Dwivedi-Yu, Roberto Dessì, Roberta Raileanu, Maria Lomeli, Luke Zettlemoyer, Nicola Cancedda, Thomas Scialom (Meta AI)
**日期**: 2023年（NeurIPS 2023）
**领域**: 大模型

## 核心问题

（1）**LLM 的固有局限**：语言模型在数学计算、事实性知识查询、实时信息获取等方面存在根本性不足。例如，GPT-3 175B 在 ASDiv 数学数据集上仅能正确回答约 54% 的问题，因为纯文本生成无法保证计算正确性。

（2）**现有工具使用方法的人工成本高**：传统让 LLM 使用外部工具的方法（如 Tool-LLM、API-Bank）需要大量人工标注数据——标注员需要标注"何时该调用工具、调用哪个工具、怎么传参"。这限制了工具集的可扩展性。

（3）**模型无法自主判断调用时机**：Few-shot prompting 方式虽无需训练，但模型仅按模板模仿，无法真正理解"什么时候该用工具、什么时候不该用"——要么滥用 API，要么该用时不用。

## 核心方法（ToolFormer）

（1）**API 调用标记化**：将每个工具 API 封装为特殊标记格式 `[API名(参数) → 返回值]`，例如 `[Calculator(12 + 7) → 19]`。这些标记直接嵌入文本流中，使 API 调用成为语言建模的一部分，模型在生成过程中遇到 `[` 即进入 API 调用模式。

（2）**自监督数据生成**：先从少量（约 250 条）人工编写的 API 调用示例出发，利用 in-context learning 让模型在大量无标注文本（CCNet 子集）中自动插入 API 调用候选。关键技巧是：对同一段文本生成多个候选 API 调用的变体（每个位置可插入不同工具），通过执行 API 获得真实返回值。

（3）**基于困惑度（Perplexity）的自监督过滤**：核心创新——对所有候选 API 调用，执行后比较插入 API 前后文本序列的 perplexity。仅保留 perplexity 降低的调用作为有效训练样本。过滤标准为加权 loss 差：若插入 API 返回后，后续 token 的 loss 显著降低（降低 ≥ 1.0），则保留该调用。这保证了模型只在"API 确实有帮助"时才学会调用。

（4）**标准 LM 微调**：用过滤后的数据（约 100M token）对 GPT-J 6.7B 进行标准语言建模微调。无需特殊 loss 函数或 RL——模型自然学会何时生成 `[` 触发 API 调用、如何填写参数。微调后模型在推理时自主决定是否调用工具。

## 实验结果

（1）**数学推理大幅提升**：在 ASDiv 数据集上，ToolFormer (GPT-J 6.7B) 达到 74.5% 准确率，超越 GPT-3 175B 的 54.2%，同时参数规模仅为 1/26。在 SVAMP 和 MAWPS 上也分别提升 12+ 个百分点。

（2）**问答任务显著改进**：在 LAMA (Google-RE) 知识探测任务上，加入搜索引擎和 QA 工具后准确率提升约 10 个百分点。模型学会了在不确定时调用工具而非胡编。

（3）**模型不会滥用工具**：经自监督过滤后，模型仅在约 5-8% 的 token 位置主动调用 API，且调用位置的准确率（即调用后确实改善了生成质量）超过 90%。消融实验显示，去掉自监督过滤机制后模型会随意插入 API 调用，性能反而下降 15% 以上。

（4）**不损害核心语言能力**：在 WikiText-103、LAMBADA 等标准语言建模和语言理解基准上，ToolFormer 的 perplexity 与 GPT-J 基座基本持平甚至略优，说明加入工具学习不会"分心"。

## 核心意义

ToolFormer 是第一个证明 LLM 可以通过自监督学习自主掌握工具使用能力的工作。它的核心贡献不在于创造了新的模型架构，而在于提出了一套简洁优雅的数据生成与过滤流水线——让模型从少量示例出发，自己探索、自己试错、自己筛选有效的工具使用模式。这一范式打破了"工具增强 LLM 需要大量人工标注"的瓶颈，为后续的 Gorilla、Berkeley Function Calling、GPT-4 的 Function Call 等奠定了方法论基础。尽管受限于单步工具调用和固定 API 格式，但"让模型自我探索工具使用"的核心思想已成为 Agent 领域的标准实践。
